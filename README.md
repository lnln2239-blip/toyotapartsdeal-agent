# Agent سحب قطع toyotapartsdeal.com

Agent بسيط (مو ذكاء اصطناعي — كود عادي) يسحب أرقام قطع OEM وبيانات التوافق
من toyotapartsdeal.com، مع نظام checkpoint/resume عبر Supabase.

## الفكرة بالمختصر

- `discover-categories.mjs` — يفتح صفحة موديل (مثل صفحة الكامري) ويطلع لك
  كل فئات القطع (محرك، فرامل، ...) ويحطها في جدول `scrape_queue`.
- `scrape-category.mjs` — يسحب الفئات وحدة وحدة من `scrape_queue`، يمشي على
  كل صفحاتها (pagination)، ويحفظ كل قطعة (رقم القطعة + السيارات المتوافقة)
  في جدول `parts_raw`. بعد كل صفحة يحدّث checkpoint، فلو انقطع (GitHub Actions
  قطعه، أو صار خطأ) يكمل من نفس المكان في التشغيلة الجاية بدل ما يبدأ من الصفر.

كل القطع تدخل بـ `verified = false` — تراجعها وتعتمدها بنفسك قبل لا تدخل بستم،
نفس بروتوكول التحقق اللي متبعينه.

## خطوات التشغيل

### 1) جهّز Supabase
1. افتح مشروع Supabase حقك (نفس اللي تستخدمه في بستم، أو مشروع جديد).
2. روح SQL Editor وشغّل محتوى `schema.sql` مرة وحدة.
3. من Settings → API خذ: `Project URL` و `service_role key`.

### 2) جهّز GitHub
1. أنشئ مستودع (repository) جديد لهالمشروع، وخلّه **Public**. هذا مهم:
   GitHub يعطي دقائق تشغيل Actions غير محدودة ومجاناً بس للمستودعات العامة —
   المستودع الخاص محدود بـ 2000 دقيقة/شهر، ومع 5 عمّال متوازيين بيخلص بسرعة.
   المفاتيح السرية (Supabase) تبقى محمية حتى لو المستودع عام، لأنها بـ Secrets
   مو بالكود نفسه.
2. ارفع محتوى المجلد فيه.
3. Settings → Secrets and variables → Actions → أضف:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_KEY`

### 3) جرّبه محلياً أول (مهم قبل لا تشغّله على نطاق واسع)
```bash
npm install
export SUPABASE_URL=...
export SUPABASE_SERVICE_KEY=...

# يطلع فئات الكامري ويحطها بالـ queue
node scripts/discover-categories.mjs https://www.toyotapartsdeal.com/toyota-camry-parts.html

# يسحب أول 3 فئات بس (تحكم فيها بـ MAX_CATEGORIES_PER_RUN)
node scripts/scrape-category.mjs
```
افتح جدول `parts_raw` في Supabase وتأكد إن `part_number` و `fitment` طالعين
صح لعدد قليل من القطع، قبل لا تشغّله بشكل تلقائي ومستمر.

**ليش هالخطوة مهمة:** الـ selectors المستخدمة (`h3` + أقرب حاوية) مبنية على
هيكلة الصفحة وقت كتابة السكربت. لو الموقع غيّر تصميمه بعدين، أول علامة
بتكون إن `parts_raw` ما يتعبى أو `fitment` يطلع فاضي — رجعلي وقتها أعدّل
الـ selectors على الهيكلة الجديدة.

### 4) شغّله تلقائياً (بتشغيل متوازي)
`.github/workflows/scrape.yml` مضبوط يشغّل **5 عمّال بنفس اللحظة كل 15 دقيقة**،
كل وحد ياخذ فئة مختلفة تلقائياً وبأمان (ما يصير تصادم بينهم). هذا يعطيك تقريباً
5 أضعاف سرعة العامل الواحد، بدون ما نزوّد سرعة الطلبات على الصفحة نفسها —
كل عامل لسا يحترم `DELAY_MS` (3 ثواني) بين طلباته.

- تقدر تزود/تقلل عدد العمّال من `matrix.worker` بالملف (مثلاً `[1,2,3,4,5,6,7,8]`).
- لا تنزل `DELAY_MS` تحت ثانيتين احتراماً لسعة الموقع، حتى لو زدت عدد العمّال.
- **مهم:** عشان الـ queue ما تفضى بسرعة مع 5 عمّال، شغّل `discover-categories.mjs`
  على أكثر من موديل (مو الكامري بس) — شوف قسم "توسيعه" تحت.

## توسيعه لموديلات ثانية أو مواقع ثانية

- **مهم مع التشغيل المتوازي:** شغّل `discover-categories.mjs` على عدة موديلات
  (كامري، كورولا، RAV4، هايلاندر...) بدري، عشان يصير عندك فئات كافية بالـ queue
  تشغّل الـ 5 عمّال بدون ما "يفضون" بسرعة. كل موديل جديد يزيد سطور بالـ queue
  بدون ما يكرر اللي موجود.
- **موديل ثاني بنفس الموقع** (كورولا مثلاً): شغّل `discover-categories.mjs`
  على رابط صفحة الموديل الجديد — بينضاف لنفس الـ queue تلقائياً.
- **موقع ثاني من نفس الشبكة** (hyundaipartsdeal.com، nissanpartsdeal.com...):
  نفس القالب العام (queue + checkpoint + Supabase) ينطبق، لكن لازم أتأكد من
  هيكلة صفحاتهم أول (ممكن تختلف شوي عن toyotapartsdeal رغم إنهم شكلهم متشابه) —
  قولي إذا تبي أبدأ بواحد منها وأسوي نفس الفحص.
